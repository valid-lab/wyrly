---
title: "Core model"
description: "Wyrly DI の中核となる objects: tokens、providers、containers、scopes、lifetimes。"
---

Wyrly の core model は小さく保たれています。ほとんどの application で必要なのは、tokens、
providers、containers、scopes、lifetimes の 5 つです。

## Tokens

Token は TypeScript type を持つ runtime key です。

```ts
const UserRepositoryToken = token<UserRepository>("UserRepository");
```

Interface や abstract capability には token を使います。Class 自体が dependency key
になる場合は、class constructor を直接登録することもできます。

## Providers

Provider は、dependency をどのように作成または返すかを container に伝えます。

Wyrly は次を support します。

- class-backed dependencies 向けの `useClass`
- constants と test doubles 向けの `useValue`
- custom construction が必要な dependencies 向けの `useFactory`
- aliases 向けの `useExisting`

## Containers

Root container は application-wide registrations を所有します。

```ts
const container = createContainer();
container.register(UserRepositoryToken, {
  useClass: PrismaUserRepository,
  lifetime: "scoped",
});
```

Root container は composition root として扱います。Domain や use case code の中ではなく、
そこで具体的な infrastructure を登録してください。

## Scopes

Scope は child resolution context です。Web apps では、adapters が通常 1 request につき
1 scope を作ります。

```ts
const scope = container.createScope();
try {
  const service = scope.resolve(MyService);
} finally {
  await scope.dispose();
}
```

Scoped dependencies は同じ scope 内で再利用され、scope が dispose されると一緒に dispose
されます。

## Lifetimes

| Lifetime | Meaning |
| --- | --- |
| `singleton` | root container につき 1 instance |
| `scoped` | scope につき 1 instance |
| `transient` | resolution ごとに新しい instance |

Dependency の state と resource ownership に合う、もっとも狭い lifetime を選んでください。

## Validation

Production 前に graph problems を検出するには、`container.validate()` を使います。

- missing providers
- circular dependencies
- invalid provider shapes
- lifetime violations

Validation は dependency wiring を checkable artifact にできるため、CI で特に有用です。
